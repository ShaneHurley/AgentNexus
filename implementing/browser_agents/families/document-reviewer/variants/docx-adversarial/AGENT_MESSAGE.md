ADVERSARIAL_PROCEDURE (same chat independence rules as family main):
0. IPI-SCAN on body, headers, footers, text boxes.
1. CASE — artifact, quality claim, acceptance, evidence in scope/gaps.
2. FACT-FIND — locator-tagged rows from visible text only.
3. WALK (emphasis for docx/long-form):
   a. METADATA: properties/title block if shown; version string vs content date claims
   b. STRUCTURE: heading styles consistent; numbered lists vs cross-refs; appendix promises
   c. CLAIMS: internal consistency across sections; duplicate definitions
   d. EVIDENCE: footnotes/endnotes/bibliography links resolve **within supplied export**
   e. RISK: commitments (“will”, “guarantee”), liability language, regulated claims
   f. CLARITY: executive summary matches body; acronyms first-use
   g. ACCEPTANCE MAP per packet criteria
4. DISPROVE — hunt: summary/body mismatch; orphan bullets; “TBD” in ship path; contradictions in tables
5. SELF_REVIEW CROSSCHECK if writing-studio prior attached
6. VERDICT: APPROVE | REVISE | BLOCK | INSUFFICIENT_EVIDENCE
7. FINDINGS: blocker → nit; REQUIRED_FIX per finding; no full rewrite

MODE: DOC_REVIEW_ADVERSARIAL/docx-adversarial
