# ANX-5 implementation contract and validation

ANX-4 merged in PR #19 after independent review and Linux/macOS CI. ANX-5 extends that baseline; ANX-6/7 remain backlog. No paid calls or changes to actual personal stores or vaults.

## Ownership
Integration: contracts/schema/owned registry metadata, memory authority, CLI, session binding/ingestion, documentation and CI. Storage worker: memory.py and its tests. Portability worker: memory_portability.py, personal_store.py and their tests. Workers use separate managed worktrees; shared edits integrate serially. Source writes use the existing approved DC PolicyGateway.

## Interfaces
MemoryAccess carries identity, originating run and EffectiveGrant. KnowledgeStore is explicit-open (never create on read); create requires confirmation, canonical store UUID, kind, meta namespace write and raw-run retention choice. First SQLite schema has checksummed migration metadata and structural validation; unsupported schemas are refused. Existing stores are not automatically downgraded or upgraded.

Owned memory-capabilities.yaml declares role maxima using kind:namespace. The memory authority binds only the selected store's kind to exact store:UUID:namespace IDs. Every task supplies all six layers; each access checks namespace, sensitivity and workspace. Installation does not authorize any store. memory.export/import/backup are typed runtime-owned operations, not generic engineering write tools. Active restrictions/revocations still apply.

Drafts carry sources, retrieval timestamps/hashes/authenticity and author/run. Defaults retrieve only accepted, current, nonconflicting records. Acceptance and revision require confirmation and current content hash. Synthetic/failed evidence cannot become factual memory. FTS returns at most eight expanded records and a conservative 4,000-token allocation; no embeddings. Dependency mismatches and missing current fingerprints exclude factual results. Cache records expire after 30 days.

Portability uses scoped hashed JSON manifests, whole-document validation before transactions, draft-only import with lineage, consistent SQLite backups and reviewed transformations for Shared promotion. Whole-store backup requires every stored namespace/data class. Deletion clears searchable content and references, increments generation and schedules tombstone purge; existing backups are not rewritten. Personal files remain authoritative; previews never initialize them, mutations validate schemas, derived artifacts record source fingerprints and stale status.

## Runtime integration
Explicit --memory-binding authorizes one session identity, store and six-layer grant. The binding contains version=1, session_id, store, grant, optional namespace/sensitivity. grant.run_id must equal session_id, and role must be the workflow parent. Research binds Research; coding binds Project or Daily; automatic Shared ingestion is denied. Configuration content and store identity are pinned in the run. Current authority is checked before ingestion; drafts record the actual run UUID.

Research retains only nonempty engine-read text whose URL is in its accepted selected source list; fixtures stay synthetic. Coding retains a bounded phase/status outcome, not arbitrary files or prompts. Missing binding creates no memory. Draft insertion is deterministic/idempotent. A configured ingestion failure blocks successful retention while preserving known provider usage; the accepted engine checkpoint remains available. No automatic acceptance or promotion.
