# Master-spec extract for the personal skill layer

Condensed from `docs/architecture/agent_orchestration_master_spec.md` Parts A6–A11 and D.2–D.4. Applies as **governance**, not as a mandate to run the full Daily Coder phase DAG on personal tasks.

## Skills (A6–A11)

- Skills accrete; require human merge; budget consolidation/retirement.
- Skills stabilize procedure (checklists, tool order, verify), not knowledge dumps.
- One skill per subtask / procedural family; resident catalog ~5–8 descriptors.
- No autonomous skill self-write; proposal + human merge only.
- Treat skill create path as supply-chain risk; provenance + clean-session tests.

## Principles that apply

- Durable state outside the model (calendar, notes, `personal-store`).
- Claim tags: VERIFIED | INFERENCE | ASSUMPTION | UNKNOWN (career extends with USER_CONFIRMED | UNSUPPORTED).
- Policy at the execution boundary for hard writes (DC/RF only in v1).
- Budgets and stop conditions enforced outside the prompt for engineering runs.

## Do not adopt for personal v1

Unbounded self-improvement; transcript as system of record; large flat always-loaded skill catalog; personal PolicyGateway/ledger/dashboard; seventh UF orchestrator.
