# Runtime defect fixes — 10 November 2026

All six defects reproduced in the [initial evaluation](evaluation-2026-11-10.md) are fixed in the source kit. The original observations remain preserved for comparison.

| Defect | Change | Verification |
|---|---|---|
| Cursor-only install omitted skills | Cursor now selects the shared project skill directory. | Both skills checked in separate installations for all four tools. |
| Fresh Cursor hook configuration lacked `version` | Adds `version: 1` when absent, without reformatting existing user entries. | Fresh install, repeat install, and unversioned existing configuration. |
| Shipped briefs failed validation | Template and example use colon headings; validator also accepts the previous standalone heading form. Empty or missing sections are rejected where a blocking event supplies the brief. | Both literal shipped briefs across Cursor, Claude, and Codex; malformed controls. |
| Returned workers stayed active | Ledger stores host, parent session, child ID, call ID, and brief hash. Returns must identify a unique dispatch; duplicate, unknown, or ambiguous returns leave other workers untouched. Start replay is idempotent. | Out-of-order/duplicate returns, session and host isolation, older events, concurrent starts, and existing database migration. |
| Repeated checks lost chronology | Request and test events receive unique IDs; each check keeps its own artifact reference. | FAIL/PASS/FAIL and PASS/FAIL/PASS preserve every observation and report the latest outcome correctly. |
| Shell flag variants bypassed guard | Tokenizes commands and parses Git flags, including option values, recursive deletion targets, working directories, and simple shell wrappers. Recognized dry runs are permitted. Invalid shell input returns exit 2. | Force flags, clean flag combinations, recursive-delete forms, directory changes, nested shells, safe controls, and all three host output shapes. No destructive command executed. |

Claude's installer now also registers `SubagentStart`. Claude and Codex record child identities at that lifecycle event, so returns can use the same child identifier. Their `PreToolUse` handler validates the brief and checks limits without creating a second dispatch row. Cursor counts and records starts in a serialized database transaction. For Claude and Codex, launches pending between PreToolUse and SubagentStart are not reserved, so concurrency checks remain best effort in that interval.

## Validation

- Python 3.12.0: **38 tests passed**, no skips.
- Default Python 3.9.13: **37 passed, 1 skipped** (the existing TOML parser test requires Python 3.11+).
- Original subprocess probe: **14/14 expectations passed**, compared with 3/14 before fixes. [Results](evidence/runtime-probe-fixed-2026-11-10.json).
- Fresh installed CLI smoke: three child dispatches returned out of order, including a duplicate; all three finished correctly. A real unittest was run against a file containing 41, then 42, then 41; the ledger preserved FAIL/PASS/FAIL and the stop warning identified the final failure. [Evidence](evidence/installed-cli-fixed-2026-11-10.json).
- Regression tests were run against the original implementation before applying fixes and reproduced the reported failures. The suite includes safe/valid controls and migration preservation checks.

The installed smoke uses direct hook payload fixtures, not hooks invoked by the IDE. No additional model-backed subagent trial was performed as part of these fixes. The original Codex discovery observation (no selectable custom agent type demonstrated) is unresolved host compatibility, not something these source changes establish as repaired. Full host loading, actual worker model selection, hook trust/denial, nine-task comparison, and the AgentNexus retirement audit remain pending in [live verification](verified.md) and [comparison](comparison.md).

## Applying the update

Rerun `install.py` for each existing target with its original `--tools` selection and `--hooks` if hook registration was enabled, then restart the host. This updates installed scripts, skills, and hook entries. The installer does not alter host approval, sandbox, or hook-trust settings.

Existing dispatch tables are migrated in a transaction and all old records are preserved. The update cannot recover already-discarded check history or infer which unidentified legacy dispatches actually returned. Such old rows should be reconciled from real evidence; the migration does not silently mark them completed.

Reproduce from the repository root:

```sh
python3.12 -m unittest discover -s simpleIDE/tests -v
python3.12 simpleIDE/docs/evidence/runtime_probe.py
```

The probe intentionally prints a JSON result and does not use its exit code to indicate failed expectations; inspect `passed` versus `total`.
